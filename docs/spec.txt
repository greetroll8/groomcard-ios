 11. GroomCard — Pet Groomer Card & Consent 
 Offline-first карточка питомца и согласие для соло/выездного грумера: порода и шерсть, флаги поведения, стиль и референс-фото, прививки, согласие на расчёс колтунов/возрастных, фото до/после и PDF-отчёт хозяину. 
 Дата: 30 мая 2026 
 Формат: отдельное подробное ТЗ 
 Стек: SwiftUI / SwiftData / PDFKit / Vision / StoreKit 2 
 Статус: ТЗ готово 
 ← К пакету подробных ТЗ 
 GroomCard — Pet Groomer Card & Consent 
 Подробное ТЗ для iPhone-only offline-first приложения для одиночного и выездного грумера, которому не нужна салонная booking-система. Это карточка питомца, согласия и фото-доказательство «до/после» с PDF-отчётом хозяину — без подписки и без облака. 
 1. Позиционирование 
 1.1. Короткое описание 
 GroomCard хранит профиль каждого питомца: порода, тип шерсти, аллергии, флаги поведения (кусается, осторожно), предпочитаемый стиль и референс-фото, срок прививки от бешенства, согласие хозяина на работу с колтунами/возрастными животными/без седации. После стрижки — фото до/после, заметки и PDF-отчёт. 
 1.2. Главный продуктовый тезис 
 Салонные SaaS (MoeGo, Gingr) отвечают на вопрос «как управлять записью и салоном». GroomCard отвечает на вопрос «что я знаю об этой собаке, на что хозяин дал согласие и как выглядела работа» — для одного мастера, офлайн, разово. 
 1.3. Категория 
 Параметр Значение 
 Платформа iOS, только iPhone 
 Режим работы Offline-first (работа в фургоне) 
 Основной ввод Фото, флаги, согласие-подпись 
 Основной вывод PDF-отчёт хозяину, согласие-PDF 
 Целевая длительность сессии 30–60 сек до/после стрижки 
 Тип приложения Карточка клиента + согласие + фото-доказательство 
 1.4. Дифференциация 
 Салонный SaaS / маркетплейс GroomCard 
 Подписка, заточка под запись Разовая оплата, карточка+согласие 
 Нет акцента на consent и риск-флаги Согласие и поведение — первичны 
 Нет офлайн-работы в фургоне Полностью офлайн 
 Pet-sitting marketplaces — другая задача Именно груминг-карточка

 6. Полный client journey 
 6.1. Первый визит 
 New pet → порода/шерсть/флаги/аллергии/прививка → consent-экран (что разрешает хозяин) → подпись → фото «до» → работа → фото «после» + заметки/стиль → PDF-отчёт хозяину. 
 6.2. Повторный визит 
 Open pet → New session (дефолты из прошлого стиля) → фото до/после → save → опц. PDF. Согласие переподписывается по настройке (каждый раз / раз в год).

 9. Экраны, формы, состояния, валидации 
 9.1. Pet profile 
 Поле Тип Обяз. Валидация 
 Кличка text Да 1–60 
 Вид/порода picker/text Да — 
 Тип шерсти picker Нет — 
 Флаги поведения chips Нет bite/anxious/senior/none 
 Аллергии/здоровье text Нет до 500 
 Прививка (бешенство) date Нет флаг при истечении 
 Хозяин picker Да — 
 9.2. Consent screen 
 Редактируемый текст согласия (расчёс vs сбривание колтунов, риски для возрастных, без седации, разрешение на публикацию фото). Подпись на canvas, дата, версия текста. PDF. 
 9.3. Grooming session 
 Стиль/длина по зонам, фото «до» (1–4), фото «после» (1–4), заметки, рекомендации хозяину, цена опц. 
 9.4. Paywall 
 Триггеры: лимит питомцев (free), PDF-отчёт/согласие, бэкап v2. План monthly/yearly/lifetime, Restore.

 15. Edge cases

 Истёкшая прививка Предупреждение, требовать подтверждение

 23. Definition of Done для MVP 
 MVP готов, когда без аккаунта и без сети грумер может: задать шаблон согласия и реквизиты; завести питомца с флагами и хозяином; получить подписанное согласие в PDF; провести сессию с фото до/после и заметками; выгрузить PDF-отчёт хозяину; увидеть истёкшую прививку; восстановить состояние после перезапуска; понять free-лимит и восстановить покупку. 
 24. Локализация и интернационализация (i18n/l10n) 
 Приложение полностью локализуется на 5 языков. Base (development) language — English. Локализуются интерфейс, документы и App Store-метаданные; пользовательский контент (заметки, имена, фото) не переводится. 
 24.1. Поддерживаемые локали 
 Локаль Код Особенности формата 
 English en (base, en-US) точка-десятичный, MM/DD/YYYY, $; имперские единицы по региону; plural one/other 
 Русский ru запятая-десятичный, DD.MM.YYYY; plural few/many/other (1/2/5) 
 Deutsch de запятая-десятичный, DD.MM.YYYY, € после суммы; строки длиннее на ~35% 
 Español es разделители по региону, €; plural one/other 
 Français fr запятая-десятичный, пробел в тысячах, € после суммы 
 24.2. Технический подход 
 Аспект Требование 
 Источник строк SwiftUI String Catalog (.xcstrings, Xcode 15+) как единый источник; комментарии для переводчиков 
 Доступ к строкам Только LocalizedStringKey / String(localized:); хардкод user-facing строк запрещён (lint-проверка) 
 Множественное число Plural-правила CLDR в .xcstrings; обязательно проверить ru (1/2/5) и en/de/es/fr (one/other) 
 Сборка строк Интерполяция с аргументами, без конкатенации; порядок слов задаёт перевод 
 Смена языка Следовать системному языку + поддержать per-app language (iOS 17 Settings) без потери данных 
 24.3. Форматирование по локали 
 Данные Требование 
 Даты/время Date.FormatStyle / .formatted(), без ручных шаблонов; хранение в UTC, показ в локали 
 Валюта Хранить ISO-код; показывать .formatted(.currency(code:)) — символ и разделители по локали 
 Числа/проценты FormatStyle; десятичный и тысячный разделители по локали 
 Единицы измерения Measurement + MeasurementFormatter (мили/км, lb/kg, °F/°C, psi/bar) по региону + ручной override 
 CSV-экспорт Машинный CSV — фиксированная точка-десятичный, запятая-разделитель, UTF-8 (BOM) независимо от UI-локали; Numbers-CSV — по локали с предупреждением 
 24.4. Локализация документов (PDF / этикетки / чеки) 
 Требование Детали 
 Язык документа По умолчанию = язык UI; на экспорте можно выбрать язык документа (клиент в другой стране) 
 Юридические тексты Отдельные локализованные редактируемые шаблоны на каждую локаль; дефолт по локали 
 Шрифты PDF-шрифт с полным покрытием кириллицы и диакритики (ru/de/es/fr) — без «тофу»/потери глифов 
 Подписи в PDF Заголовки таблиц, итоги, статусы — из String Catalog, не хардкод 
 24.5. App Store, OCR и ввод 
 Область Требование 
 App Store метаданные Локализованные subtitle, описание, keywords, скриншоты на 5 локалей; локализованные privacy/terms 
 Подписки StoreKit Локализованные названия/описания планов; цены — App Store managed 
 Vision OCR recognitionLanguages включает ru/en/de/es/fr там, где есть OCR; авто по локали + ручной выбор 
 Клавиатура/ввод Полная поддержка диакритики и кириллицы, без ASCII-ограничений 
 Особенности приложения: текст согласия и отчёт хозяину — локализованные редактируемые шаблоны; вес питомца lb/kg по региону; флаги поведения и тип шерсти локализованы. 
 24.6. Acceptance критерии локализации 
 Критерий Проверка 
 Нет хардкод-строк Lint/таргет-проверка — 0 нарушений
